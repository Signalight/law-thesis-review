# 国际经济法论文审查（iet-law-thesis-review）

读取学生上传的 Word 论文，按检查清单找出问题，并输出一份**带修订 + 批注**的审查稿 Word 文件。

## 输入

- **单篇**：一个 .docx 文件路径。
- **批量**：一个文件夹路径；自动逐个处理其中所有 .docx（忽略以 ~$ 开头的临时文件）。

## 输出

对每个输入文件 原文件名.docx，生成：

1. **原文件名_审查稿.docx** —— 主输出。原标题与所有学生信息保持原样；内含教师用 **修订模式** 改写的文字（w:ins / w:del）与 **Word 批注**。
2. **原文件名_审查说明.md** —— 副产物。总体评语 + 待修改清单（老师存档/回顾用）。

## 铁律

1. **绝不修改原文件**；输出另存为新文件，文件名为原文件名加 _审查稿。
2. **不动论文标题**；**不添加、不删除学生信息**（姓名、学号、指导教师等，若原文有则保留，没有也不补）。
3. **评语客观、以指出问题为主**；总体评语须就文章的**立意、结构、论证方式**等宏大层面作统一点评（见“总体评语”一节），而不只报细枝末节；可以简单认可，但不要空泛鼓励、不要夸大。
4. 一律使用**中文标点**；引号第一层用中文双引号“”，嵌套用中文单引号‘’，不使用直引号。

## 依赖

- **自包含**：scripts/apply_edits.py、models.py、add_comment.py 与 review_docx.py 一起供货，无需额外安装 word-docx。
- Python 3 + lxml + pydantic（apply_edits/models 依赖 pydantic）。

## 工具：review_docx.py

~~~bash
# 1) 提取正文 + 段索引（paragraph_index 与底层 w:body 直接段落一致）
python scripts/review_docx.py extract 输入.docx --out 输出目录

# 2) 生成审查稿（spec.json 见下）
python scripts/review_docx.py review 输入.docx --spec spec.json --out 输入_审查稿.docx [--author "批注作者"]
~~~

### spec.json 形状

~~~json
{
  "summary": "简短、客观、以指出问题为主的总体评语",
  "author": "可选，批注/修订作者；缺省自动检测",
  "edits": [
    {"operation": "replace", "paragraph_index": 165, "old_text": "利用", "new_text": "运用"},
    {"operation": "delete",  "paragraph_index": 83,  "old_text": "这样的"},
    {"operation": "insert",  "paragraph_index": 90,  "new_text": "（补充说明）"}
  ],
  "comments": [
    {"paragraph_index": 83, "anchor_text": "美国", "text": "此处建议更精确。"}
  ]
}
~~~

edits 以修订模式写入；comments 以 Word 批注写入。paragraph_index 取自 extract 输出的 [P####]。

## 检查清单

本 skill 使用**打包的自查清单**：references/checklist.md（已合并硕士/本科两类要求，并增补国际经济法常见问题与发散性问题）。如需自定义清单，可将覆盖文件放在本目录 references/ 下（同名覆盖）。

## 批注风格

批注采用“短、直接、命令式或问句”的风格，无需再读取任何样稿，按以下要点写：

- **简短**，一句到两三句；多用“请…”“建议…”“删除”“不要”“核实”“是否有依据？”“这里要给出英文全称。”
- **指出具体问题并给方向**，不写长篇大论；以质疑/提醒为主，客观、不空泛表扬。
- 对明显严重的问题可用“！！！”强调，但不要滥用。
- **每条批注必须锚定所引注的句子**：即 comments 里 anchor_text 必须是该批注针对的那一句/短语，使读者一眼知道针对哪一句。
- 典型示例（批注 → 所引注的句子，均为通用化示例）：
  - “脚注与正文严重不匹配，请核对。” → “某条法律或案例的论述句。”
  - “这里要给出英文全称，并核实该规则是否存在。” → “首次出现某外文缩写或外部规则处。”
  - “这个标题无法涵盖在上一级标题下，请调整标题。” → “某一级标题文字。”
  - “页码范围太宽，建议限缩。” → “正文引注某书／某条文处。”
- 引号层级：外层用中文双引号“”，内层用中文单引号‘’；批注与评语中不出现英文直引号。

## 总体评语（宏观统一点评）

`summary`（总体评语）必须对文章**宏大层面**作统一点评，而不是只罗列细碎错误。至少覆盖：

- **立意**：选题是否有价值、问题意识是否清晰、创新点／贡献点是否成立。
- **结构**：章节安排是否合理、逻辑衔接是否顺畅、详略是否得当、结论是否回应研究问题。
- **论证方式**：论证是否充分、是否以叙代论、概念是否界定清楚、案例／数据是否支撑观点。
- **方法**：研究方法是否恰当、样本与范围是否说明、结论边界是否审慎。
- **文献**：文献综述是否有评价、与选题的关联、新旧与中外文献的平衡、著录是否规范。

写法：先给整体判断（可作简单认可），再**分点指出主要问题并给方向**；客观、克制，不空泛表扬。

## 何时用“修订” / 何时用“批注”

| 情况 | 用 |
|---|---|
| 错别字、语法、术语错用、标点、书名号、数字格式、法条或案例名称笔误、可直接确定的格式问题 | **修订**（tracked edit） |
| 需要学生自己改/澄清/论证的问题，如"脚注与正文不匹配""请核实是否存在该规则""建议展开解释""这里为什么是这个框架""此标题与上位标题冲突" | **批注**（comment） |
| 结构、逻辑、章节安排、评价性问题 | **批注** |

同一位置原则上只做一种：要么修订、要么批注。若必须都做，批注应锚定在**不被修订的稳定相邻文字**上。

## 批注的两个重点类型

1. **部分整体问题 —— 以标题为批注对象**。当某个部分（章、节、小节）存在整体性、方向性问题时，不要在某一句正文上批注，而是**把批注锚定在该部分的标题上**，对该部分整体给出评价。典型情形：
   - 偏题：整段未围绕本文主题（如“国企”特殊性问题）展开，只写一般知识；
   - 背景／基础知识过多，与论证融合不足；
   - 通篇为理论分析、缺少案例或实证支撑；
   - 所提问题其实并不具“特殊性”，普通主体同样存在，需论证其与本文主题的关联。
   批注示例（锚定标题）：“这一部分其实都是基础知识，有些过多；可将其与国企情况结合，写一条国企困难再补一般规定。”“很多问题抛开国企身份仍然存在，请思考其特殊性。”“目前困境多停留在理论分析，欠缺案例。”

2. **缺依据、缺澄清处 —— 补充批注要求出处／具体化**。在具体位置写批注，要求提供依据或澄清。典型情形：
   - 过于宽泛、方向不明（“面临重构”“构建开放新格局”的具体内容）；
   - 提到客观事实或具体主体却没有出处（如列举某几家大型企业）；
   - 专有名词、政策概念未解释（如“国货国运”）；
   - 与普通主体（如民企无船承运人）的区别未说明；
   - 关键时间、数量、比例等不具体；
   - 概念的适用关系需澄清（如“连带责任”是否等于“刺破公司面纱”）。
   批注示例：“出处。”“具体是什么意思？建了更多航道？”“专有名词需要解释。”“和非国企的区别是？”“具体时间？”“这似乎也是‘强企业’的问题，不是国企的特殊问题。”

## 工作流（单篇）

1. 拿到输入 .docx 路径。
2. python scripts/review_docx.py extract 输入.docx --out <临时目录>。
3. 阅读 document.md（带 [P####]）、paragraphs.json、footnotes.json。
4. 对照检查清单逐项审查，定位问题所在段落与具体文字。
5. 编写 spec.json：edits（可确定的修改）+ comments（需学生处理的）+ summary（总体评语）。
6. python scripts/review_docx.py review 输入.docx --spec spec.json --out 输入_审查稿.docx。
7. 查看输出里的“未写入项”；若有批注因锚点与修订冲突而未能写入，改用相邻稳定文字重新锚定并重跑。
8. 汇报：输出文件路径、共多少修订/多少批注、哪些未写入、总体评语。

## 工作流（批量）

1. 输入是一个文件夹。
2. 列出其中所有 .docx（跳过 ~$ 临时文件）。
3. 对每个文件执行上面单篇工作流的 2–7 步；每个文件独立 extract + 独立 spec + 独立 review。
4. 最后汇总：N 个文件全部处理、每个文件的问题数（修订/批注数）、整体评语与共性高频问题。

## 作者信息（批注/修订作者）

- 默认自动检测顺序：Windows 注册表（Office/WPS 用户名）→ 输入 docx 的 lastModifiedBy（若 ≠ 原 creator）→ 留空。
- 也可以用 --author "姓名" 或 spec 的 author 字段显式指定。
- 学生信息：保留原样，不作增删。

## 已知限制

- 修订/批注只能作用于**正文直接段落**；**表格、文本框内文本**无法原地修订/批注（可阅读，但只能把批注锚定到最近的正文句）。
- **脚注内文本**无法直接添批注；脚注问题的批注应锚定在引出该脚注的正文句。
- **目录、页码、字体字号、行距、页边距**等排版问题不能被本 skill 直接改写，只能以批注提醒人工处理。
- 对无法自动判断的内容（如图表、页码、查重、AI 生成整段痕迹），以批注提示人工核对。

## 发散性高频问题（checklist.md 已列入，这里提示重点）

国际经济法论文除通用问题外，尤其注意：

- WTO 用“成员方”，不用“成员国”；涉台/港/澳称谓规范（中国台北等）。
- 条约、协定、国际组织、仲裁机制名称与简称准确（ICSID / ISDS / UNCITRAL / GATT / WTO 等），首次出现给中外全称。
- 案例名称、裁判结果真实可查；引用来源具体到页码/条款。
- 外文文献格式统一（作者姓名、标题大小写、Article、paras.、pp.）。
- “可借鉴某国做法”必须写出具体做法，不能笼统。
- 单边制裁、反制裁、软法/硬法、管辖/争端解决等概念要用准、要解释。
